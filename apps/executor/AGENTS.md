# Executor 设计约束

本文件记录已确定的设计，按任务逐步实现。身份、会话绑定和并发约定见[全局架构](../../docs/ARCHITECTURE.md#跨模块约定)。

## 目录结构

- `src/index.ts` 装配 CLI 根命令、子命令与运行所需的 Layer。
- `src/cli/` 按子命令组织，处理参数和终端交互。每个子命令模块只导出对应的子命令。
- `src/services/` 按服务职责组织，每个模块公开对应的 Effect 服务及装配所需的 Layer 或 Layer 工厂。服务配套类型和错误的导出遵循[模块公开接口规范](../../docs/CODING_STANDARDS.md#模块职责与公开接口)。

## 程序组织

- CLI 与 daemon 采用 Effect 管理异步操作、预期错误、取消及资源清理；网络、文件、子进程和服务管理器在明确边界适配，外部数据通过共享的 Effect Schema 或本地配置 Schema 校验。
- daemon、连接与工具调用分别管理生命周期；连接断开不自动中断或重试已有工具调用。将取消传递给底层请求与进程，包装为 Effect 本身不保证底层操作停止。

## CLI 与 daemon

- CLI 负责发起 OAuth 设备授权、绑定 Executor 和管理本地配置。daemon 负责连接 Server、接收工具请求和执行本地工具，两者属于同一个 Executor 包。
- 安装时注册服务并配置开机自启，由平台服务管理器托管 daemon，使其独立于 CLI 和终端的生命周期运行。
- CLI 完成设备授权和 Executor 绑定，保存该实例的专用凭据后，请求服务管理器启动 daemon。CLI 随后可退出。服务启动成功与 Server 认证连接成功分别报告。
- CLI 与 daemon 以对应的本地用户身份运行，共用该实例的配置、凭据和执行权限，不默认以 root 执行工具。
- 每份实例配置对应一个 `executorId` 和一个 daemon；同一设备上的多个实例使用不同配置区分。

## 设备授权与绑定

- `rabi login` 采用交互式设备授权，首版要求用户能在某台设备上操作浏览器，暂不支持无人参与的首次绑定。Executor 支持 SSH 与无桌面环境，无需启动本地 Web 服务或接收浏览器回调。
- CLI 通过 HTTPS 向云端 Server 申请授权，显示授权网址和 `user_code`；用户可以在另一台设备的浏览器中登录 Rabi 并确认绑定。网页登录与确认交互见 [Web 设计](../web/AGENTS.md#登录与设备授权)。
- CLI 保留秘密的 `device_code`，按 Server 指定间隔轮询领取凭据；不通过终端收集 Rabi 账号密码。字段语义与 PKCE 适用边界见[设备授权协议](../../packages/protocol/AGENTS.md#设备授权)。
- 等待授权期间支持 Ctrl+C 停止等待；按协议处理等待中、降低轮询频率、用户拒绝和申请过期，网络超时后降低重试频率。停止本地等待不等于撤销服务端申请。
- 绑定后 daemon 使用已保存的实例专用凭据自动运行，不依赖网页登录会话；凭据有效期与自动续期方案见 [Server 待定事项](../server/AGENTS.md#账号与设备授权)。

## 服务与连接生命周期

- daemon 启动时读取实例配置；无凭据时正常退出，有凭据时主动建立 WSS 并向 Server 认证。凭据文件的出现本身不承担唤醒职责，由 CLI 在保存成功后启动服务。
- 服务重启策略须区分需要用户处理的正常退出与异常退出，避免无凭据或凭据失效时反复启动。
- 网络故障时退避重连。凭据失效、绑定被撤销时停止重连，提示重新授权。被 Server 明确替换的旧连接停止自动重连，避免实例互相接管。
- 通过 Ping/Pong 与超时检测失联，避免仅凭本地 WebSocket 状态判断对端在线。
- 服务启动应满足无人登录时的开机自启要求；首先支持 Linux systemd，其他平台服务适配后续扩展。具体服务配置、凭据存储位置、心跳与超时参数待定，资源优化暂缓。

## 本地执行

- 执行前落实本地授权的工作目录与工具范围；Server 请求和账号绑定不能扩大本地权限。
- 按会话、运行和工具调用标识关联请求、执行状态与结果，支持多个会话并发，并遵守全局工作目录冲突约束。
- 重连时配合 [Server](../server/AGENTS.md#调度与恢复) 核对原调用状态；连接切换不代表原工具停止，不据此重新执行。
