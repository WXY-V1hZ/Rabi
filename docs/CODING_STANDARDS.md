# 编码规范

供开发者与 Agent 编码、审查时使用；与 `AGENTS.md` 配合执行。格式和静态规则以仓库工具配置为准，本文约束工具无法充分检查的设计与行为。

## 首要原则：奥卡姆剃刀

- 在满足正确性、安全性和可维护性的方案中，选择概念、状态和依赖最少的实现。
- 只实现当前需求；新增抽象、配置项、依赖或架构层次时，必须有实际问题作为依据。
- 先用直接实现；重复代码在业务含义和变化原因一致、提取后更清楚时再复用，不为消除表面相似而耦合模块。
- 性能优化应有测量依据；必要的输入限制和资源上限不属于提前优化。

## 可读性与模块边界

- 名称表达业务含义，布尔值表达明确判断；注释解释原因、约束和权衡，避免复述代码。
- 函数围绕一个明确目的组织，优先使用守卫语句减少嵌套；仅在改善理解或复用时拆分。
- 实现细节留在模块内部，减少导出；业务计算与网络、文件、进程等副作用在需要独立验证时分离。
- 跨包通过声明的依赖和公开入口访问，不跨目录导入其他包的内部源码；共享协议放在 `packages/protocol`，不依赖应用实现或特定运行环境。
- 模块导入不隐式启动服务、连接或任务；在明确入口完成初始化，并提供对应的清理路径。

## TypeScript 与数据建模

- 箭头函数使用大括号包裹函数体，返回值显式使用 `return`，不使用隐式返回。
- 保持严格类型检查；优先类型推断，在公开边界和推断不清楚处显式标注。
- 外部未知数据使用 `unknown`，校验后再使用；类型声明和断言不能代替运行时校验。参考 [TypeScript 类型收窄](https://www.typescriptlang.org/docs/handbook/2/narrowing.html)。
- 不用 `any`、双重断言、非空断言或检查禁用注释掩盖错误；确需兼容时限制作用范围，并说明成立条件或原因。
- 用判别联合表达互斥状态，避免多个布尔值产生非法组合；明确区分缺失、空值和失败。
- 遵循各包现有模块与导入约定；新增运行时 API、语法和依赖须兼容项目声明的运行版本。

## 异步、错误与资源

- 每个 Promise 都有明确的等待或错误处理路径；后台任务也必须处理失败，不能仅用 `void` 隐藏未处理拒绝。
- 网络请求和工具执行应有超时及取消机制；释放连接、文件、子进程、监听器和定时器，覆盖成功、失败与取消路径。
- 在能恢复或转换为接口响应的边界处理错误；保留必要上下文，不吞错，不将失败伪装成空结果或成功。
- 重试必须限定次数和条件；有副作用的操作先明确幂等性，避免重复执行。并发任务须限制数量和输出规模。
- 共享状态更新应考虑并发、重复请求和断线重连；涉及持久化时，明确状态变更的原子边界。

## 安全与执行边界

- 在网络、配置、文件和工具调用入口校验数据形状、长度、范围及路径；客户端和模型输出均视为不可信输入。
- 服务端校验身份以及对会话、任务和执行器的访问权限；执行器按已授权的工作目录和能力执行，协议消息本身不构成授权。
- 启动程序优先使用独立参数数组，避免拼接 shell 命令；确需 shell 语义时，明确区分命令与数据并校验权限和范围。参考 [Node.js 子进程安全说明](https://nodejs.org/api/child_process.html)。
- 路径访问校验规范化后的实际目标及符号链接影响，防止越出授权目录；错误响应和日志不得泄露密钥、令牌及敏感内容。

## React

- 保持渲染纯净，事件行为放在事件处理函数中；能从 props 或现有状态计算的数据，不再保存一份同步状态。
- Effect 用于与外部系统同步，并提供必要的清理和过期请求处理；不通过禁用依赖检查解决状态问题。参考 [React Effect 指南](https://react.dev/learn/you-might-not-need-an-effect)。
- 状态尽量靠近使用位置；有实际共享需求时再提升状态或引入状态库。优先语义化 HTML，并提供表单标签、键盘操作和明确的加载、错误反馈。

## 验证与维护

- 按变更风险验证行为：重点覆盖业务分支、输入边界、失败和取消路径；修复缺陷时优先加入能复现问题的回归测试。
- 测试断言可观察行为，避免绑定内部实现或为简单转发、纯格式修改增加无收益测试；当前缺少测试设施时，说明实际验证方法和局限。
- 完成前运行适用的仓库检查，具体命令与提交要求见 `AGENTS.md`；检查通过不能代替行为验证，也不能证明所有规范均已满足。
