## 回复模板

````markdown
## {第 N 步 · 要实现的行为}

{用一句话说清这一步完成后，用户能观察到什么。}

{解释这次改动接入现有流程的哪个位置，以及为什么放在那里。
只讲动手前需要理解的概念。}

### {要改的文件或操作}

[{文件名}]({绝对路径}:{行号}) · {新增文件 / 替换某段 / 在某行之后插入}

```ts
// 代码
```

### 验收

运行 `{命令}`，应看到 `{可观察结果}`。
{如果本步涉及失败分支，再给一个输入变化和对应的预期结果。}
````

## 注意事项

- 如果涉及多个文件，则重复「文件或操作」这一段。
- 概念解释、架构讨论、错误分析及代码审查不强制使用模板，应直接回答用户的问题。
- 优先解释设计选择背后的原因，避免只告诉用户如何操作。
